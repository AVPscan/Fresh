# Fresh — Среда исполнения нового поколения

**Fresh** — это первая **среда исполнения приложений (Runtime Environment)**, полностью независимая от ОС, процессора, видеокарты, внешних библиотек и даже страны. Это не фреймворк и не библиотека. Это **новый слой реальности** между данными и наблюдателем.

---

## 📦 Один бинарник — везде и навсегда

Одно приложение, собранное с Fresh, работает **одинаково** на:
- Linux (x86, ARM, RISC-V)
- macOS (Intel, Apple Silicon)
- Windows (включая Cygwin, WSL)
- Docker-контейнерах
- По SSH и в текстовой консоли
- На встраиваемых системах (Raspberry Pi, ESP, микроконтроллеры)

Без доработок. Без рантаймов. Без виртуализации.

**Размер бинарника:** от 16 до 32 КБ (зависит от платформы).

---

## ⚡ Производительность как вызов

Fresh не просто быстр — он **обходит ограничения железа**:
- Не нужна видеокарта (графика через шрифт терминала / Браэль)
- Не нужен X11/Wayland (прямой вывод в терминал)
- Не нужен GPU для рендеринга (CPU + RDTSC + умный кэш)
- Одно ядро CPU — достаточно для полноценной работы
- FPS ограничен только скоростью вашего терминала

## 🌍 Полная независимость

### От страны и электросети
- Поддержка частот сети: **от 0,1 Гц до 1000 Гц**
- 0,1 Гц — экстремально низкие частоты (специальные установки)
- 50 Гц — Европа, Россия, Азия
- 60 Гц — Америка, часть Азии
- 400 Гц — авиация, корабли, спецтехника
- 1000 Гц — промышленность, лаборатории, максимальная производительность
- **HotSwap**: изменение частоты на лету без перезапуска
- Работает в любой точке мира: на земле, под водой, в поезде, в самолёте, в космосе

### От времени
- **96-битный таймер** — основан на частоте сети, не зависит от процессора
- Время до обнуления: **~2,5 триллиона лет** (при 1000 Гц)
- **~50 триллионов лет** (при 50 Гц) — больше времени существования вселенной
- Абсолютная синхронизация с реальным временем
- Поддержка любых часовых поясов и форматов

### От процессора и разрядности
- Автоматическая адаптация к разрядности процессора через `typedef uintptr_t Cell`
- Поддержка 8, 16, 32, 64-битных архитектур
- Масштабирование типов данных в зависимости от `CellPow`
- Сдвиги вместо умножений — максимальная производительность на любом железе

### От монитора и разрешения
- Холст до **2^61 × 2^61** ячеек
- Автоматическая подстройка под любое разрешение терминала
- Пропорция холста **32:9** — вписывается в любой монитор (16:9, 21:9, 32:9)
- Поддержка Браэля — каждый символ = 2×4 точки, увеличивает разрешение без потерь
- **Автоадаптация к масштабу шрифта** — изменяете шрифт, Fresh пересчитывает всё автоматически

## 🖥️ Графика и визуализация

### Холст и ячейки
- Каждая ячейка холста — полноценный элемент с:
  - UTF-8 текстом (до 4 байт)
  - Визуальной длиной (0, 1, 2 знакоместа)
  - Цветом (любая глубина: 3, 8, 24 бита)
  - Атрибутами (7 потоковых атрибутов)
  - Палитрой и структурой данных

### Цвет и палитры
- Глубина цвета: **3, 8, 24 бита** (изменяется в рантайме)
- **Две палитры**:
  - Первая — генерируется через **целочисленную тригонометрию (sin)** — плавные, органичные переходы
  - Вторая — **простое деление спектра** — чёткие, контрастные цвета
- **0 — чёрный, 1 — белый**, остальное — разбитый спектр
- **+1** — это специальный цвет, который меняется во времени (привязан к таймеру)
- Автогенерация палитр под любую глубину цвета
- 256 цветовых оттенков (0-255)

### Адаптивные макросы Ink(n) и Fon(n)
- `Ink(n)` — код цвета для текста
- `Fon(n)` — код цвета для фона
- Работают для **любого числа цветов** (автоматически адаптируются)
- Упрощают написание кода — не нужно думать о количестве цветов
- `n > 7` — специальные цвета (последний в палитре, меняющийся во времени)
- `n <= 7` — базовые цвета из диапазона

### Браэль
- Каждый символ UTF-8 может быть сегментом Браэля
- 2 точки по горизонтали, 4 по вертикали
- Увеличивает разрешение без изменения кода
- 8K знакомест → 16K точек Браэля

## 🪟 Оконная система (спрайты)

### Окна без рамок
- **До 65 535 окон** одновременно
- Окно — это полноценный объект-спрайт:
  - Позиция (`Xr`, `Yr`) — две переменные для перемещения
  - Размер (`W`, `H`)
  - Слой (`Layer`) — Z-порядок
  - Видимость — один бит
  - Курсор (позиция внутри окна)
  - Автоперенос строк
  - Ожидание загрузки данных

### Слои и ротация
- Полноценная слоистая архитектура
- Z-порядок управляется через слои
- Ротация окон (WDown/WUp) — переключение слоёв
- WTop — поднять окно наверх

### Статические и динамические окна
- Статические: привязаны к координатам холста
- Динамические: привязаны к экрану (вьюпорту)
- Автоматическая адаптация к изменению размера окна

## ⌨️ Событийная модель

### Полный набор событий
- **157 вариативных событий** с клавиатуры
- **98 системных событий** (включая таймер)
- **Событие K_NO** — выполняется на каждой итерации цикла
- **Событие Timer** — привязано к частоте сети
- **События мыши** — полная поддержка X10

### Расширенная ASCII-клавиатура
- Поддержка всех управляющих последовательностей
- Расширенный набор: K_Ctrl_*, K_F1-F15, K_ALT_*, и т.д.
- Поддержка комбинаций клавиш
- Буфер клавиш с обработкой повторов

### Мышь X10 — полная свобода
- Поддержка всех кнопок мыши (левая, средняя, правая)
- **Горизонтальный скролл** — любой мыши через `shift+roll`
- Четыре кода — и любая мышь получает премиальные возможности
- **Две скорости перемещения**:
  - Обычная скорость
  - Ускоренная (через Ctrl) — прыгаем пространствами

### Буфер событий
- Накопление событий в реальном времени
- Обработка очереди событий
- Привязка функций к событиям через векторы

## ⏱️ Время и таймер

### 96-битный таймер
- Основан на частоте электрической сети
- Счётчик: 6 элементов по 16 бит = 96 бит
- Время до обнуления: **~2,5 триллиона лет** (при 1000 Гц)
- **~50 триллионов лет** (при 50 Гц) — больше времени существования вселенной

### Частота сети
- Поддержка любых частот: **от 0,1 Гц до 1000 Гц**
- Изменение в рантайме через HotSwap
- Абсолютная синхронизация с реальным временем

### Частота APM человека
- Частота нажатия клавиш: **от 50 до 1000 Гц**
- 50 Гц — минимальная комфортная скорость
- 1000 Гц — максимальная, реальное время без задержек
- Адаптация к скорости ввода

## 🧩 Управление памятью

### Полный контроль
- Своя система выделения памяти через mmap
- Полная отвязка от malloc/free
- Автоматическое выравнивание
- Защита от утечек
- Экономия памяти: все индексы хранятся в минимально возможных типах

### Масштабирование типов
- `ugoc` — беззнаковый для индексов (16/32/64 бит)
- `goc` — знаковый для координат (16/32/64 бит)
- `udgoc` — расширенный беззнаковый
- `dgoc` — расширенный знаковый
- Автоматический выбор разрядности при компиляции

## 🔄 Адаптивность и гибкость

### SysWrite — единственная точка выхода
- Вся визуализация идёт через `SysWrite`
- Если заменить `SysWrite` — Fresh перестаёт быть терминалом
- Может выводить куда угодно: в файл, в сеть, на экран, в базу данных
- Полная свобода выбора слоя визуализации

### Автоадаптация
- К масштабу шрифта — изменяете шрифт, Fresh подстраивается
- К разрешению терминала — автоматический пересчёт
- К частоте сети — HotSwap без перезапуска
- К разрядности процессора — выбор типов при компиляции

### Нет рамок — нет ограничений
- Окна-спрайты — без декораций
- Две переменные — и объект появился/исчез
- Полная свобода позиционирования
